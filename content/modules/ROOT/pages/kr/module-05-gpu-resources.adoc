= GPU 및 리소스 모니터링

로그는 무슨 일이 일어났는지, 트레이스는 왜 일어났는지 보여줍니다 -- 그러나 *메트릭*은 얼마나, 얼마나 빠르게를 보여줍니다. 이 모듈에서는 {ocp-short} Console 내장 모니터링을 사용하여 {demo-app-name}의 GPU 활용률과 Pod 리소스 소비를 관찰합니다.

== 학습 목표

이 모듈을 완료하면 다음을 수행할 수 있습니다:

* {ocp-short} Console을 통해 GPU 활용률과 메모리 메트릭을 조회합니다
* AI 애플리케이션 워크로드의 Pod CPU 및 메모리 사용량을 모니터링합니다
* LLM 추론에 전형적인 버스트형 GPU 활용 패턴을 해석합니다

== GPU 모니터링이 중요한 이유

AI 워크로드는 전통적인 애플리케이션과 다르게 동작합니다:

* *버스트형 활용* -- LLM 추론은 강렬한 GPU 스파이크와 유휴 기간을 번갈아 생성합니다
* *메모리 압박* -- 대형 모델은 상당한 VRAM을 소비하며, 부족하면 OOM 실패가 발생합니다
* *비용 영향* -- GPU는 고비용이므로, 활용률을 이해하면 배포 규모를 적정화할 수 있습니다

== 실습: GPU 및 Pod 메트릭 관찰

=== 내장 대시보드 사용

{ocp-short}는 쿼리 작성 없이 GPU와 Pod 메트릭을 보여주는 사전 구축된 대시보드를 제공합니다.

. *{ocp-short} Console*에서 *Observe* > *Dashboards*로 이동합니다.
. 대시보드 드롭다운에서 *Kubernetes / Compute Resources / Namespace (Pods)*를 선택하고 네임스페이스 필터를 `demo`로 설정합니다.
+
네임스페이스 내 모든 Pod의 CPU 사용량, 메모리 사용량, 네트워크 I/O를 한눈에 확인할 수 있습니다.

. GPU 메트릭을 보려면 드롭다운에서 GPU 관련 대시보드(예: *NVIDIA DCGM Exporter*)를 선택합니다.

image::img-gpu-metrics.png[Observe > Dashboards -- GPU 및 Pod 리소스 메트릭]

{demo-app-name}에 몇 가지 요청을 보내고 대시보드를 관찰합니다. 추론 중에 *GPU 스파이크*가 발생하고 요청 사이에 유휴 상태로 돌아가는 것을 확인할 수 있습니다 -- 이 버스트 패턴은 LLM 워크로드에 전형적입니다.

[TIP]
====
임의 쿼리를 실행하려면 *Observe* > *Metrics*로 전환하여 PromQL을 직접 입력하십시오. 예를 들어, `DCGM_FI_DEV_GPU_UTIL`은 실시간 GPU 컴퓨트 활용률을, `DCGM_FI_DEV_FB_USED`는 VRAM 소비량을 표시합니다.
====

== 모듈 요약

*수행한 내용:*

* NVIDIA DCGM 메트릭을 사용하여 GPU 활용률, 메모리, 온도를 조회했습니다
* PromQL로 Pod CPU 및 메모리 사용량을 모니터링했습니다
* LLM 추론 중 버스트형 GPU 패턴을 관찰했습니다

*핵심 요점:*

* LLM 워크로드의 GPU 활용률은 *버스트형*입니다 -- 추론 중 스파이크, 요청 간 유휴
* GPU 메모리(VRAM)가 일반적으로 제한 요소입니다; 모니터링으로 OOM 실패를 방지합니다
* 메트릭을 트레이스(모듈 4) 및 로그(모듈 3)와 연관시키면 엔드투엔드 가시성을 확보할 수 있습니다

*프로덕션에서 모니터링할 항목:*

* *GPU 컴퓨트 활용률* (`DCGM_FI_DEV_GPU_UTIL`) -- 지속적으로 높은 값은 GPU가 병목임을 나타냅니다
* *VRAM 사용량* (`DCGM_FI_DEV_FB_USED`) -- 한계에 근접하면 OOM 실패 위험이 있습니다
* *GPU 온도* (`DCGM_FI_DEV_GPU_TEMP`) -- 80도C 이상이 지속되면 열 스로틀링이 발생할 수 있습니다
* *Pod CPU/메모리* -- 꾸준한 증가는 메모리 누수 징후이며, 한계 근처의 스파이크는 OOMKilled 위험이 있습니다

[NOTE]
====
알림, 임계값, 다중 메트릭 패널이 있는 커스텀 대시보드를 구성하려면 {ocp-short} Prometheus 데이터 소스와 *Grafana*를 통합하는 것을 고려하십시오. Grafana를 사용하면 GPU, Pod, 애플리케이션 수준 메트릭을 단일 화면에 결합하는 맞춤형 뷰를 구축할 수 있습니다.
====
