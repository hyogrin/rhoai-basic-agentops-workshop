= 소개 -- AgentOps란?

전통적인 DevOps는 운영 환경에서 소프트웨어 시스템을 모니터링, 디버깅, 유지보수하는 방법을 제시했습니다. 그러나 AI 에이전트는 새로운 과제를 도입합니다: *비결정적 동작*, *멀티 에이전트 오케스트레이션*, *LLM 품질 변동*, *분산 도구 호출* 등이 있습니다.

*AgentOps*는 이러한 현실에 대응하기 위해 관측성(Observability) 사례를 확장합니다. 요청 비율과 지연 시간을 추적하는 것을 넘어, 에이전트 추론 경로를 추적하고, 토큰 소비를 측정하며, 도구 호출 성공 여부를 검증하고, 출력 품질을 지속적으로 평가해야 합니다.

본 워크숍에서 그 방법을 배웁니다.

== 전통적 모니터링의 한계

전통적인 애플리케이션 모니터링은 HTTP 요청, 오류율, 응답 시간을 추적합니다. 일반적인 API의 경우 다음과 같은 정보를 확인할 수 있습니다:

[source,text]
----
POST /api/chat -> 200 OK, 2.3s response time
----

그러나 AI 기반 애플리케이션에서는 다음 정보를 *확인할 수 없습니다*:

* 에이전트가 어떤 도구를 어떤 순서로 호출했는지
* LLM 호출이 몇 번 발생했는지 (3번인지 8번인지)
* 전체 2.3초 중 어떤 호출이 1.8초를 소비했는지
* 에이전트가 데이터베이스에서 올바른 데이터를 조회했는지
* 에이전트가 그럴듯한 응답을 생성하는 동안 도구 호출이 조용히 실패했는지

AI 에이전트는 *분산적으로* 실패합니다. 하나의 사용자 질문이 여러 LLM 호출, 다수의 도구 실행, 수많은 데이터베이스 쿼리를 트리거할 수 있습니다. 무언가 실패하거나 잘못된 데이터를 반환할 때, 근본 원인을 찾으려면 전체 의사결정 경로를 추적해야 합니다.

[cols="1,2",options="header"]
|===
| 과제 | 중요한 이유

| *비결정적 동작*
| LLM 변동으로 인해 동일한 질문이 다른 결과를 생성할 수 있어 버그 재현이 어렵습니다

| *멀티 스텝 오케스트레이션*
| 단일 요청이 LLM 호출, 도구 실행, 데이터 조회로 분산되며 각각 독립적으로 실패할 수 있습니다

| *무음 도구 실패*
| 도구가 빈 데이터를 반환해도 에이전트는 계속 진행하여 불완전한 정보로 응답을 생성합니다

| *연쇄 지연*
| 느린 데이터베이스 쿼리가 LLM 호출을 지연시키고, 이것이 응답을 지연시키지만 전통적인 메트릭으로는 병목 지점을 특정할 수 없습니다

| *토큰 비용 가시성*
| 요청별 토큰 추적 없이는 비용 할당과 예산 예측이 불가능합니다
|===

이것이 AgentOps에 전문화된 관측성이 필요한 이유입니다: HTTP 래퍼뿐 아니라 의사결정 과정 *내부*를 볼 수 있어야 합니다.

워크숍을 완료하면 다음을 수행할 수 있습니다:

* {ocp-short} Console 로그 뷰어와 `oc logs`를 사용하여 애플리케이션 로그를 탐색합니다
* MLflow에서 요청 트레이스, Span, 도구 호출, LLM 실행을 분석합니다
* {ocp-short} 내장 모니터링을 통해 GPU 활용률과 Pod 리소스 소비를 모니터링합니다

== AgentOps 관측성의 세 가지 축

image::img-three-pillars-observability.png[관측성의 세 가지 축]

[cols="1,2,2",options="header"]
|===
| 축 | 답변하는 질문 | 본 워크숍의 도구

| *로그*
| _정확히 무슨 일이, 언제 발생했는가?_
| {ocp-short} Console + `oc logs`

| *트레이스*
| _왜 발생했는가? 실행 경로는?_
| MLflow Tracing

| *메트릭*
| _얼마나? 얼마나 빠르게? 부하는?_
| {ocp-short} Observe (Prometheus + NVIDIA DCGM)
|===

이 세 가지 축을 함께 사용하면 AI 애플리케이션에 대한 완전한 가시성을 확보할 수 있습니다: 로그로 상세 이벤트를, 트레이스로 요청 흐름과 추론 과정을, 메트릭으로 시스템 상태와 리소스 사용량을 파악합니다.

== 사전 요구 사항

시작하기 전에 다음 사항을 확인하십시오:

* {rhoai-short} {rhoai-version}이 설치된 {ocp} 클러스터가 실행 중이어야 합니다
* 클러스터에 GPU 노드가 하나 이상 사용 가능해야 합니다 (예: NVIDIA L4, L40S, A100)
* 관리자가 GPU Hardware Profile을 생성해 두어야 합니다
* MLflow Tracking Server가 배포되어 있어야 합니다 (`sno-enable-all-features-35.sh` 사용)
* `redhat-ods-applications` 네임스페이스에 PostgreSQL이 실행 중이어야 합니다 (`sno-setup-maas-35.sh` 사용)
* GPU 메트릭을 위해 NVIDIA DCGM Exporter가 활성화되어 있어야 합니다
* 강사가 제공한 로그인 자격 증명(사용자명 및 비밀번호)이 준비되어 있어야 합니다
