= Explore Application Logs in OpenShift Console

In Module 2 you deployed the {demo-app-name} and generated traffic. Every interaction triggered LLM calls, tool invocations, and database queries -- all of which produced log output. In this module you will explore those logs using the {ocp-short} Console.

{ocp-short} provides a built-in log viewer that lets you inspect container output directly from the Console -- no additional log aggregation stack required. Every container's STDOUT and STDERR is captured automatically by the container runtime.

== Why Logs Matter for AgentOps

For AI applications, logs reveal:

* *LLM request/response cycles* -- what the model received and returned
* *Tool call results* -- whether tools succeeded or failed
* *Error traces* -- stack traces, timeouts, and unexpected exceptions
* *MLflow trace IDs* -- correlation points between logs and traces (Module 4)

== Exercise 1: View Pod Logs from the Console

=== Step 3.1: Navigate to the Backend Pod

. In the *{ocp-short} Console*, navigate to *Workloads* > *Pods*.
. Make sure the *Project* dropdown at the top is set to `demo`.
. Click on the *planner-backend* pod.

image::img-pods-list.png[Pod list in the demo namespace]

=== Step 3.2: View the Log Stream

[start=4]
. Click the *Logs* tab.

image::img-pod-logs-tab.png[Backend pod Logs tab showing live output]

You should see the backend application's log output in real time. The log stream includes FastAPI startup messages, incoming request logs, LLM call details, and MLflow trace events.

=== Step 3.3: Filter Logs by Container

If a pod has multiple containers (sidecars, init containers), use the *Container* dropdown above the log viewer to select a specific container.

For the `planner-backend` pod, select the *backend* container to focus on the application logs.

== Exercise 2: Search and Filter Logs

=== Step 3.4: Search Within Logs

Use the *Search* bar at the top of the log viewer to filter for specific keywords:

* Search `error` or `exception` to find error events
* Search `mlflow` to find trace-related log entries
* Search `token` or `inference` to find LLM interaction logs

image::img-pod-logs-search.png[Searching within pod logs]


[TIP]
====
Click the *arrow-down* button (bottom-right) to auto-scroll and follow the log stream in real time. Click *Pause* to freeze the output for inspection.
====

== Exercise 3: View Logs via the Terminal (Optional)

You can also view logs from the Web Terminal using `oc logs`:

*Tail the live backend log stream:*
[source,sh,role="execute"]
----
oc logs -f deployment/planner-backend -n demo
----

*Show only the last 50 lines:*
[source,sh,role="execute"]
----
oc logs deployment/planner-backend -n demo --tail=50
----

*Filter for specific patterns with grep:*
[source,sh,role="execute"]
----
oc logs deployment/planner-backend -n demo --tail=200 | grep -i "error\|exception\|mlflow"
----

Press `Ctrl+C` to stop following the log stream.

*What you accomplished:*

* Filtered and searched log output for errors, LLM interactions, and MLflow events

*Key takeaways:*

* {ocp-short} captures all container STDOUT/STDERR automatically -- no code changes required
* The Console log viewer provides real-time streaming, container selection, and keyword search
* `oc logs` gives you CLI-level access with grep and tail for deeper analysis
* Logs tell you *what exactly happened and when* -- the foundation for debugging
